# Рецепты

Готовые к копированию решения двух задач, которые рано или поздно возникают у
каждого боевого Mini App: доказать на сервере, что запуск действительно
пришёл из Telegram, и вызывать бэкенд через Serverless-мост с типизированными
ошибками. Оба рецепта предполагают, что SDK уже инициализирован через
`init_sdk()`.

## Валидация `initData` на бэкенде

SDK никогда не проверяет поле `hash` на клиенте: для проверки нужен токен
бота, а токен бота ни в коем случае не должен попадать на фронтенд. Задача
фронтенда — передать исходную строку запуска на бэкенд как есть:

```rust,ignore
use telegram_webapp_sdk::core::context::TelegramContext;

let raw_init_data =
    TelegramContext::get_raw_init_data().map_err(|error| JsValue::from_str(error))?;
// Отправьте `raw_init_data` на сервер как есть — не перекодируйте и не меняйте порядок пар.
```

На бэкенде (нативный Rust, не WASM) пересчитайте подпись ровно так, как
описано в Bot API: соберите data-check-string из отсортированных пар
`key=value` (без `hash`), выведите секретный ключ из токена бота и сравните
хэши за время, не зависящее от значения.

```toml
# Cargo.toml бэкенда
hmac = "0.12"
sha2 = "0.10"
percent-encoding = "2"
```

```rust,ignore
use hmac::{Hmac, Mac};
use percent_encoding::percent_decode_str;
use sha2::Sha256;
use std::collections::BTreeMap;
use std::time::{SystemTime, UNIX_EPOCH};

type HmacSha256 = Hmac<Sha256>;

/// Проверяет исходную строку `initData` по токену бота.
///
/// При успехе возвращает разобранные поля. Отклоняет запуски старше
/// `max_age_secs`, чтобы перехваченный набор нельзя было переиграть.
pub fn validate_init_data(
    raw: &str,
    bot_token: &str,
    max_age_secs: u64,
) -> Result<BTreeMap<String, String>, String> {
    let mut fields = BTreeMap::new();
    let mut received_hash = None;
    for pair in raw.split('&') {
        let (key, value) = pair.split_once('=').ok_or("malformed initData pair")?;
        let decoded = percent_decode_str(value)
            .decode_utf8()
            .map_err(|_| "initData value is not valid utf-8")?
            .into_owned();
        match key {
            "hash" => received_hash = Some(decoded),
            _ => {
                fields.insert(key.to_owned(), decoded);
            }
        }
    }
    let received_hash = received_hash.ok_or("initData has no hash field")?;

    let data_check_string = fields
        .iter()
        .map(|(key, value)| format!("{key}={value}"))
        .collect::<Vec<_>>()
        .join("\n");

    let mut key_mac =
        HmacSha256::new_from_slice(b"WebAppData").map_err(|_| "fixed key must be valid")?;
    key_mac.update(bot_token.as_bytes());
    let secret_key = key_mac.finalize().into_bytes();

    let mut mac = HmacSha256::new_from_slice(&secret_key).map_err(|_| "derived key invalid")?;
    mac.update(data_check_string.as_bytes());
    let signature = decode_hex(&received_hash).ok_or("hash is not hex-encoded")?;
    mac.verify_slice(&signature)
        .map_err(|_| "initData signature mismatch")?;

    let auth_date: u64 = fields
        .get("auth_date")
        .and_then(|value| value.parse().ok())
        .ok_or("initData has no auth_date")?;
    let now = SystemTime::now()
        .duration_since(UNIX_EPOCH)
        .map_err(|_| "system clock is before the epoch")?
        .as_secs();
    if now.saturating_sub(auth_date) > max_age_secs {
        return Err("initData is too old, reject the launch".to_string());
    }
    Ok(fields)
}

fn decode_hex(value: &str) -> Option<Vec<u8>> {
    if !value.len().is_multiple_of(2) {
        return None;
    }
    (0..value.len())
        .step_by(2)
        .map(|i| u8::from_str_radix(&value[i..i + 2], 16).ok())
        .collect()
}
```

Чек-лист:

- Сравнивайте через `verify_slice` (постоянное время), а не через `==` на
  hex-строках.
- Отклоняйте устаревший `auth_date` — иначе перехваченный URL работает
  бесконечно.
- Считайте любое поле с фронтенда недоверенным, пока эта функция не вернула
  `Ok`; разобранный на клиенте `user` годится только для отображения.

## Типизированные вызовы Serverless с обработкой ошибок

`api::serverless::call` сериализует входной объект, ждёт Promise моста и
десериализует результат — один покрывает весь roundtrip:

```rust,ignore
use serde::{Deserialize, Serialize};
use telegram_webapp_sdk::api::serverless::{self, EndpointError};

#[derive(Serialize)]
struct BalanceInput {
    user_id: i64,
}

#[derive(Deserialize)]
struct Balance {
    amount: i64,
    currency: String,
}

async fn fetch_balance(user_id: i64) -> Result<Balance, EndpointError> {
    serverless::call("getBalance", &BalanceInput { user_id }).await
}
```

Ошибки приходят как декодированный [`EndpointError`](https://docs.rs/telegram-webapp-sdk/latest/telegram_webapp_sdk/api/serverless/struct.EndpointError.html)
с платформенным `kind`, HTTP-`status` и необязательными `parameters`. Его
`Display` уже добавляет подсказку по восстановлению, поэтому для человека
достаточно залогировать ошибку; ветвитесь по `kind`, когда приложение может
справиться само:

```rust,ignore
async fn show_balance(user_id: i64) {
    match fetch_balance(user_id).await {
        Ok(balance) => log(&format!("{} {}", balance.amount, balance.currency)),
        Err(error) => match error.kind.as_str() {
            "UNAUTHORIZED" => restart_auth(),
            "TOO_MANY_REQUESTS" => schedule_retry(),
            _ => log(&error.to_string()),
        },
    }
}
```

- Пустой `kind` и `status` `0` означают клиентский сбой (нет моста, payload
  не (де)сериализуется) — чините вызывающий код, а не эндпоинт.
- `error.hint()` вернёт ту же подсказку как `&'static str`, если её нужно
  обработать программно.
- Сам эндпоинт обязан проверять запуск (предыдущий рецепт) — Serverless
  передаёт `initData`, но не поручится за него, если эндпоинт принимает
  произвольный HTTP-трафик.
